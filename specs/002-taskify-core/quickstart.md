# 快速验证指南：Taskify 核心协作功能

本指南给出端到端可运行的验证场景，用于证明 002 功能在真实运行环境中工作。接口细节见 `contracts/`，数据模型见 `data-model.md`，实施步骤见 `tasks.md`（`/speckit-tasks` 生成）。

## 前置条件

- 001 基础设施已就绪：前端（Vue 3 + pnpm）、后端（Java 21 + Maven）、中间件（PostgreSQL、Redis、Nacos、RocketMQ）可用。
- 后端中间件：`cd backend && docker compose up -d`（复用 001 `docker-compose.yml`）。
- 预置数据：5 名预置用户（1 产品经理、4 工程师）与 3 个示例项目已由迁移/种子初始化。

## 启动

```bash
# 后端：新增 project/notification 服务随其他服务一起构建与启动
cd backend && mvn clean package -Dmaven.test.skip=true
docker compose -f docker-compose.app.yml up -d   # 含 gateway/auth/project/notification

# 前端
cd frontend && pnpm install && pnpm dev
```

## 端到端验证场景

### 1. 登录与项目总览（用户故事 1）

1. 用预置账号登录。
2. 进入项目列表，确认看到 3 个示例项目。
3. 创建新项目（名称 + 描述），确认其出现在列表。

**期望**：项目创建成功并进入列表；空名称被一致校验错误拒绝。

### 2. 创建并分配任务（用户故事 2）

1. 打开某项目，默认看到**看板视图**，可切换到**任务列表视图**。
2. 在「待办事项」列创建任务（标题必填、可留空负责人）。
3. 点击任务卡片，从右侧滑出**任务详情抽屉**，查看标题/描述/负责人/评论，并可修改任务。

**期望**：新任务默认位于「待办事项」列；不指定负责人亦可创建（未分配状态）。

### 3. 看板移动与相邻列约束（用户故事 3）

1. 桌面：将「待办事项」列的任务拖拽到「进行中」列（`vue-draggable-plus`）。
2. 尝试将「待办事项」列的任务直接拖到「已完成」列（跨列）。

**期望**：相邻列移动成功，列归属更新并实时同步给其他查看看板的用户（<1s、无需刷新）；跨列移动被拒绝，卡片回弹并提示。

### 4. 移动端看板（用户故事 3，规格 Q3）

1. 将浏览器缩到手机宽度，打开看板。

**期望**：一次仅显示一列，顶部列切换器可在四列间切换，**无横向滚动**；任务移动通过抽屉内「上一列/下一列」按钮完成。

### 5. 评论与权限（用户故事 4）

1. 在任务详情抽屉中发表评论。
2. 编辑/删除自己的评论（成功）；用另一账号尝试编辑/删除他人评论（被拒）。

**期望**：评论按时间顺序展示；仅作者可编辑/删除。

### 6. 实时通知（用户故事 5）

1. 用户 A 创建任务并指派给用户 B。
2. 观察用户 B 界面（不刷新）：铃铛图标出现未读角标；打开下拉面板看到「新任务」通知。
3. A 修改该任务、移动该任务，B 分别收到「任务修改」「看板变更」通知。
4. B 将通知标记为已读，未读角标减少。

**期望**：通知在事件后 <3s 送达（SSE，无需刷新）；未读/已读状态与角标正确。

## 测试命令

```bash
# 前端单元/组件测试
cd frontend && pnpm test          # Vitest：相邻列校验、评论权限、通知组件

# 前端 E2E
cd frontend && pnpm e2e           # Playwright：看板拖拽、评论、通知

# 后端测试
cd backend && mvn test            # JUnit 5 + Testcontainers：move 相邻列校验、评论权限、事件→通知
```

## 验收对照（成功标准）

- SC-001：登录 → 建项目 → 建首个任务 → 指定负责人，2 分钟内完成。
- SC-002：看板移动后新列归属 <1s 反映、无需刷新。
- SC-003：通知 <3s 送达、无需刷新。
- SC-004：任务始终恰好属于四列之一。
- SC-005：全新环境首次启动后 5 用户 + 3 项目即可用。
- SC-006/SC-007：关键旅程端到端流畅；移动端看板单列、无横向滚动、可切换列。
