# 快速验证指南：表格视图与视图级筛选/分组/排序（第二视图）

本指南说明如何端到端验证本特性，供评审与实现者运行。字段与接口定义见 [data-model.md](./data-model.md) 与 [contracts/task-view-api.md](./contracts/task-view-api.md)，此处不重复。

## 前置条件

- 后端各服务可启动（`taskify-auth`、`taskify-project`、`taskify-notification`、`taskify-gateway`），依赖 PostgreSQL、Redis、RocketMQ（见仓库根 README 与 `backend/docker-compose.yml`）。
- 前端依赖已安装：在 `frontend/` 下执行 `pnpm install`。
- 已完成 Flyway 迁移（含本特性 `V4__add_task_priority.sql`）。

## 启动

```bash
# 后端：按仓库既有方式启动各服务（示例为 taskify-project）
cd backend && ./mvnw -pl taskify-project spring-boot:run   # 或使用 Docker Compose

# 前端
cd frontend && pnpm dev
```

## 验证场景

### 1. 表格视图浏览与筛选/分组/排序

1. 以任一预置用户登录，打开任一项目。
2. 切换到「表格」视图，确认全部任务以表格呈现，列含标题、状态、负责人、优先级、截止时间。
3. 应用"只看我的任务"筛选，确认仅显示负责人为自己的任务。
4. 选择"按负责人分组"，确认任务按负责人聚合并显示分组标题；未分配任务归入「未分配」。
5. 选择"按截止日排序"，确认任务按截止日期升/降序排列；空截止日排末尾。

**预期**：结果符合三者叠加；刷新/重进项目后，该视图的配置仍被恢复。

### 2. 批量编辑任务字段

1. 在表格视图中勾选多条任务。
2. 用批量工具条将负责人改为某用户、设置优先级、修改截止时间，提交。
3. 确认所有选中任务同时更新，未选中的任务不变。
4. 尝试批量移动任务到非法目标列（如从「待办事项」直接到「审查中」），确认整批被拒绝且提示错误，数据不变。

**预期**：变更持久化；非法批量编辑不产生部分生效（对应 FR-008/FR-009）。

### 3. 两视图共享数据源与实时同步

1. 在表格视图中修改某任务（或批量编辑）。
2. 切换到看板视图，确认该任务更新后的状态/负责人/优先级已体现，无需手动刷新。
3. 用另一浏览器/用户登录同一项目，在任一侧修改任务，确认另一侧在无需刷新页面下同步更新。

**预期**：两视图一致，跨用户实时同步（对应 FR-010/FR-011）。

### 4. 看板泳道分组

1. 在看板视图启用"按负责人"泳道，确认每列内任务按负责人横向分组，未分配任务归入「未分配」泳道。
2. 切换到"按优先级"泳道，确认按高/中/低分组，未设置优先级的任务归入「无优先级」泳道。
3. 移动某任务到相邻列，确认其保持在其泳道内，并同步到表格视图。
4. 关闭泳道，确认恢复普通四列视图。

**预期**：泳道分组正确、可关闭、与表格同步（对应 FR-012/FR-014/FR-015）。

### 5. 手机宽度适配

1. 将视口缩至手机宽度，打开表格视图与泳道视图。
2. 确认无页面级横向滚动，任务信息仍可完整查看与操作。

**预期**：响应式适配，无横向滚动（对应 FR-022）。

## 自动化验证

```bash

cd frontend && pnpm test

# 前端端到端测试（表格编辑→看板同步主流程）
cd frontend && pnpm e2e

# 后端集成测试（优先级字段、批量编辑接口，含 Testcontainers PostgreSQL）
cd backend && ./mvnw -pl taskify-project test

# 质量门禁
cd frontend && pnpm lint && pnpm build
```

**预期**：全部通过；静态检查、类型检查、测试与构建无新增告警或错误（对应 SC-006）。
