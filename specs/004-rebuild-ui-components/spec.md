# 功能规格说明书：UI 组件体系重建与复用

**功能分支**：`004-rebuild-ui-components`

**创建日期**：2026-10-23

**状态**：草稿

**输入**：用户描述："当前 components/ui/ 下的组件是 AI 手写的 shadcn 风格仿制品，而非官方 registry 组件；业务组件和页面存在重复实现、未复用 UI 组件的问题。目标：1. 清空并重建基础 UI 组件：移除 components/ui/ 下所有现有组件，通过 shadcn-vue 官方 registry 重新安装以下组件：按钮、输入框、文本域、选择器、复选框、开关、表单、对话框、抽屉、下拉菜单、提示消息、表格、标签页、卡片、徽标、骨架屏、分页。2. 重写业务组件：components/ 和 layouts/ 下所有业务组件必须基于上述 UI 组件实现，禁止自写基础控件或重复实现已有 UI 能力。3. 重写 /design 页面：该页面所有界面元素必须复用 UI 组件。"

## 用户场景与测试（必填）

### 用户故事 1 - 重建基础 UI 组件库（优先级：P1）

前端 components/ui/ 下现有 17 个手写的 shadcn 风格组件（按钮、输入框、文本域、选择器、复选框、开关、表单字段、对话框、抽屉、下拉菜单、提示消息、表格、标签页、卡片、徽标、骨架屏、分页），它们是从头仿写的仿制品，与官方组件库存在差异且难以维护。作为维护者，我希望清空这些手写组件，改由官方组件库提供同名能力，使基础组件拥有单一、可信的实现来源。

**为何此优先级**：基础 UI 组件是所有业务组件与页面的地基；若地基仍是仿制品，后续一切「复用」都无从谈起，因此必须最先完成。

**独立测试**：可独立验证——清空 components/ui/ 后，从官方组件库重新安装指定的 17 类组件，并确认每类组件能正常渲染、交互且通过可访问性检查，无需依赖业务组件或页面的改动。

**验收场景**：

1. **给定** 项目已清空 components/ui/ 下所有手写组件，**当** 从官方组件库安装指定的 17 类组件时，**则** 每类组件均来自官方组件库，不再存在手写仿制品。
2. **给定** 已安装的基础组件，**当** 单独渲染任一组件时，**则** 其外观与官方组件库一致，且基础交互（点击、聚焦、键盘操作、状态切换）正常。
3. **给定** 已安装的基础组件，**当** 进行可访问性检查时，**则** 组件满足 WCAG AA 基线（语义化标记、键盘可导航、足够对比度、屏幕阅读器兼容）。
4. **给定** 指定的 17 类组件清单，**当** 逐一核对时，**则** 每一类均有对应的官方组件实现，无遗漏。

---

### 用户故事 2 - 业务组件与布局复用基础组件（优先级：P2）

当前业务组件与布局中存在自写基础控件和重复实现（例如自行拼装的按钮、输入、弹层、状态组件等），与基础 UI 组件能力重叠。作为维护者，我希望重写 components/ 与 layouts/ 下所有业务组件与布局，使其一律复用基础 UI 组件，消除自写基础控件与重复实现。

**为何此优先级**：业务组件与布局是产品界面与交互的实际载体，只有它们真正复用基础组件，才能消除重复实现、实现单一实现来源（对应章程原则 VII「UI 组件复用」）。

**独立测试**：可独立验证——在基础组件已就绪后，审查并重写全部业务组件与布局，确认其中不再出现自写基础控件或与基础组件重复的实现，且原有功能与交互行为不变。

**验收场景**：

1. **给定** 基础 UI 组件已就绪，**当** 审查 components/ 与 layouts/ 下任一业务组件或布局时，**则** 其中使用的基础控件（按钮、输入、弹层、选择、开关、表格、卡片、徽标、骨架屏、分页、提示等）均复用基础 UI 组件，而非自写实现。
2. **给定** 某业务组件需要现有基础组件不具备的能力，**当** 实现时，**则** 通过组合或扩展既有基础组件实现，而非复制或另写一套等价控件。
3. **给定** 重写后的业务组件与布局，**当** 运行既有功能（登录、项目列表、项目详情、看板、任务详情、通知等）时，**则** 行为与交互与重构前一致，无功能回归。
4. **给定** 重写后的业务组件与布局，**当** 运行项目的质量门禁（静态检查、测试与构建）时，**则** 全部通过且无新增告警或错误。

---

### 用户故事 3 - 重写 /design 设计画廊页复用 UI 组件（优先级：P3）

/design 页面当前直接展示手写组件，是仿制品的集中展示页。作为维护者，我希望重写该页面，使其所有界面元素复用重建后的官方 UI 组件，作为产品设计系统的唯一权威展示。

**为何此优先级**：设计画廊是设计系统的展示入口，其复用与否直接反映组件体系是否真正统一；但它不影响核心业务功能，故优先级低于业务组件。

**独立测试**：可独立验证——在基础组件已就绪后，重写 /design 页面，确认页面中所有界面元素均复用基础 UI 组件，无自写控件或游离样式。

**验收场景**：

1. **给定** 基础 UI 组件已就绪，**当** 打开 /design 页面时，**则** 页面正常渲染，展示所有指定的基础 UI 组件。
2. **给定** /design 页面源码，**当** 审查其界面元素时，**则** 所有元素均复用基础 UI 组件，无自写控件或重复实现。
3. **给定** /design 页面，**当** 在手机宽度下浏览时，**则** 布局适配且无横向滚动。

---

### 边界情况

- 当官方组件库中某个组件不具备当前手写组件已提供的特定能力时，如何处理？（应通过组合或扩展官方组件补齐，而非保留手写实现。）
- 当业务组件当前依赖手写组件的 props/slots/事件，与官方组件 API 不一致时，如何迁移？（迁移时保持业务组件对外行为不变，内部适配官方 API。）
- 当清空 components/ui/ 后仍有引用残留（例如旧导入路径），导致构建或类型检查失败时，如何保证不遗漏？（以全量类型检查与构建通过作为门禁。）
- 当某些状态类组件（如加载态、空态）自身拼装了基础控件时，是否纳入复用范围？（纳入——凡属 components/ 下的组件均须复用基础组件。）

## 需求（必填）

### 功能需求

- **FR-001**：系统必须清空 components/ui/ 下所有手写 UI 组件，改由官方组件库提供。
- **FR-002**：系统必须提供以下 17 类基础 UI 组件，且全部来自官方组件库：按钮、输入框、文本域、选择器、复选框、开关、表单、对话框、抽屉、下拉菜单、提示消息、表格、标签页、卡片、徽标、骨架屏、分页。
- **FR-003**：系统不得在基础 UI 组件目录中保留任何手写仿制品或与官方组件库重复的实现。
- **FR-004**：components/ 与 layouts/ 下的所有业务组件与布局必须复用基础 UI 组件，禁止自写基础控件。
- **FR-005**：当既有基础组件不满足业务需求时，必须通过组合或扩展既有组件实现，禁止复制等价实现。
- **FR-006**：/design 页面的所有界面元素必须复用基础 UI 组件，禁止自写控件或游离样式。
- **FR-007**：重构后的所有界面必须满足可访问性基线（WCAG AA：语义化标记、键盘可导航、足够对比度、屏幕阅读器兼容）。
- **FR-008**：重构不得改变既有功能与交互行为；所有既有用户旅程（登录、项目、看板、任务、通知等）必须保持一致。
- **FR-009**：重构后项目必须通过既有质量门禁（静态检查、测试套件与构建），且无新增告警或错误。

### 关键实体（若功能涉及数据则包含）

本特性为代码结构重构，不引入新的持久化数据。涉及的组件类别作为范围界定：

- **基础 UI 组件**：位于 components/ui/ 下、由官方组件库提供、可被业务组件与页面复用的原子/通用控件（上述 17 类）。
- **业务组件**：位于 components/ 下承载具体业务交互的组件（如任务、项目、看板、通知、认证、状态等）。
- **布局组件**：位于 layouts/ 下定义应用整体框架的组件（应用布局、应用抽屉等）。
- **页面**：路由对应的顶层界面，其中 /design 为设计画廊页。

## 成功标准（必填）

### 可度量成果

- **SC-001**：components/ui/ 下 17 类基础组件 100% 来自官方组件库，手写仿制品数量归零。
- **SC-002**：components/ 与 layouts/ 下所有业务组件与布局中，自写基础控件与重复实现的数量归零（经代码审查确认 100% 复用）。
- **SC-003**：/design 页面所有界面元素 100% 复用基础 UI 组件，无游离样式。
- **SC-004**：重构后项目通过全部既有质量门禁（静态检查、测试与构建），且既有用户旅程无功能回归。
- **SC-005**：重构后的界面保持 WCAG AA 可访问性基线，无新增可访问性缺陷。

## 假设

- 官方组件库（shadcn-vue registry）已在仓库中初始化并可用，17 类组件均可从其 registry 获取。
- 「提示消息」对应官方组件库中的 toast（sonner）能力；「表单」对应官方组件库中的 form（含 field/label 等配套）。
- 本次仅进行 UI 组件体系重构，不新增业务功能、不改变后端 API 与数据模型。
- 重构范围限定于 frontend 的 components/、layouts/ 与 /design 页面；其余页面仅作最小适配（引用路径等），不改变其行为。
- 业务组件与布局对外暴露的 props/slots/事件保持不变，仅内部实现改为复用官方组件。
- 组件文件命名与目录结构以官方组件库约定为准，业务代码中的导入路径随之更新。
